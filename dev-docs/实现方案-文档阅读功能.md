# 文档阅读功能技术方案

## 一、需求概述

在应用中添加一个文档阅读标签页，支持导入和阅读多种格式的文档（PDF、Markdown、LaTeX等），类似于主页的网页条目展示方式。

### 核心需求
1. 支持多种文档类型（PDF、Markdown、LaTeX、Text等）
2. 文档列表展示（按日期分组，类似主页）
3. 文档导入功能（从文件管理器选择）
4. 文档阅读功能（根据类型选择不同的阅读器）
5. 预留扩展接口，方便后续添加新的文档类型

### 设计原则
- **抽象层设计**：使用抽象模型和接口，不局限于PDF
  - 所有核心类使用 `Document` 命名（如 `DocumentItem`、`DocumentDao`、`DocumentFragment`），而非 `Pdf` 命名
  - 保持抽象层与具体实现的分离，为将来支持其他文档类型预留扩展空间
  - 只有真正PDF特定的实现细节才使用PDF相关命名（如 `PdfRenderer`）
- **可扩展性**：新增文档类型只需添加枚举和渲染逻辑
  - 在 `DocumentType` 枚举中添加新类型
  - 在 `DocumentViewerActivity` 中添加对应的渲染方法
  - 无需修改数据模型、数据库结构、列表展示等通用逻辑
- **代码复用**：复用现有的列表展示、搜索、删除等逻辑
  - `DocumentFragment` 和 `DocumentAdapter` 对所有文档类型通用
  - 数据库操作、文件管理、UI交互等逻辑与文档类型无关
- **渐进式实现**：先实现PDF，再逐步支持其他类型
  - MVP阶段：只实现PDF的完整功能
  - 后续扩展：根据 `DocumentType` 选择不同的渲染方式

### 2.2 核心组件

#### 2.2.1 DocumentType 枚举
定义支持的文档类型，支持扩展。

```java
public enum DocumentType {
    PDF("PDF", ".pdf"),
    LATEX("LaTeX", ".tex"),
    MARKDOWN("Markdown", ".md"),
    TEXT("文本", ".txt");
    
    // 根据文件路径自动识别类型
    public static DocumentType fromFilePath(String filePath);
}
```

#### 2.2.2 DocumentItem 模型
统一的文档数据模型，类似 LinkItem。

```java
public class DocumentItem {
    private long id;
    private String title;           // 文档标题
    private String filePath;        // 文件路径（应用私有目录）
    private DocumentType type;      // 文档类型
    private long timestamp;         // 创建时间
    private long fileSize;          // 文件大小（字节）
    private String remark;          // 备注
    private boolean isPinned;       // 是否置顶
    private int clickCount;         // 打开次数
}
```

#### 2.2.3 数据库设计

**表名：`documents`**

| 字段名 | 类型 | 说明 |
|--------|------|------|
| `_id` | INTEGER | 主键，自增 |
| `title` | TEXT | 文档标题 |
| `file_path` | TEXT | 文件路径（应用私有目录） |
| `document_type` | TEXT | 文档类型（枚举值字符串） |

| `remark` | TEXT | 备注 |

**SQL 创建语句：**
```sql

    _id INTEGER PRIMARY KEY AUTOINCREMENT,

    document_type TEXT NOT NULL,
    timestamp INTEGER NOT NULL,
    file_size INTEGER DEFAULT 0,
    remark TEXT,

```

#### 3.2.3 DocumentViewerActivity
文档阅读器，根据文档类型选择不同的渲染方式。

**设计原则：抽象层与具体实现分离**

1. **命名规范**：
   - Activity 类名使用 `DocumentViewerActivity`（抽象层命名），而非 `PdfViewerActivity`
   - 保持与 `DocumentItem`、`DocumentDao` 等抽象层命名一致
   - 只有PDF特定的实现细节（如 `PdfRenderer`）才使用PDF命名

2. **扩展机制**：
   - 根据 `document.getType()` 动态选择渲染方式
   - 每种文档类型有独立的渲染方法（`renderPdf()`、`renderMarkdown()` 等）
   - 新增文档类型只需添加新的渲染方法，无需修改现有代码

3. **当前实现（MVP阶段）**：
   - 只实现了 `renderPdf()` 方法
   - 使用 Android 系统内置的 `PdfRenderer`（API 21+），无需外部依赖
   - 支持PDF目录功能、翻页、缩放等基础功能

4. **未来扩展**：
   - 添加 `renderMarkdown()`：使用 WebView + Markdown.js 渲染
   - 添加 `renderText()`：使用 TextView 显示纯文本
   - 添加 `renderLatex()`：使用 WebView + MathJax 渲染LaTeX

**代码结构：**

**抽象层设计说明：**

- **为什么使用 Document 命名？**
  - `DocumentViewerActivity` 是通用的文档查看器，不局限于PDF
  - 保持与 `DocumentItem`、`DocumentDao`、`DocumentFragment` 等抽象层命名一致
  - 为将来支持 Markdown、LaTeX、Text 等类型预留扩展空间

- **抽象层与具体实现的关系：**
  - **抽象层**（Document命名）：`DocumentItem`、`DocumentType`、`DocumentDao`、`DocumentFragment`、`DocumentAdapter`、`DocumentViewerActivity`
  - **具体实现**（类型特定）：`PdfRenderer`（PDF渲染引擎）、`renderPdf()`（PDF渲染方法）
  - 抽象层负责数据模型、数据库操作、UI展示等通用逻辑
  - 具体实现负责特定文档类型的渲染和交互

- **扩展新文档类型的步骤：**
  1. 在 `DocumentType` 枚举中添加新类型（如 `EPUB`）
  2. 在 `DocumentViewerActivity` 的 `onCreate()` 中添加新的 case 分支
  3. 实现对应的渲染方法（如 `renderEpub()`）
  4. 无需修改数据模型、数据库、列表展示等通用逻辑

#### 3.2.4 系统PDF打开器注册

**功能说明：**
应用注册为系统PDF文件打开器，用户可以从文件管理器或其他应用中直接选择本应用打开PDF文件。

**实现方式：**

1. **AndroidManifest.xml 配置**
   - 在 `DocumentViewerActivity` 中添加多个 `intent-filter`
   - 支持 `ACTION_VIEW` + MIME类型（`application/pdf`）
   - 支持 `ACTION_VIEW` + 文件扩展名（`.pdf`）
   - 支持 `ACTION_VIEW` + content URI（Android 10+）
   - 支持 `ACTION_SEND`（分享PDF文件）

2. **DocumentViewerActivity 增强**
   - 支持三种打开方式：
     - **内部打开**：通过 `document_id` 从应用内部打开
     - **外部打开**：从文件管理器或其他应用打开PDF（通过URI）
     - **分享打开**：接收分享的PDF文件
   - 自动导入：从外部打开时，自动复制到应用私有目录并创建记录
   - 去重处理：检查文件是否已存在，避免重复导入
   - URI权限处理：正确处理 content:// URI 的权限

**使用场景：**
1. 从文件管理器打开：长按PDF文件 → 选择"打开方式" → 选择"读享"
2. 从其他应用分享：在其他应用中分享PDF → 选择"读享"
3. 从应用内部打开：在文档列表中点击PDF文件

**技术要点：**
- Android 10+ 使用 content:// URI，无需存储权限
- 自动获取URI持久权限（`takePersistableUriPermission`）
- 支持 file:// 和 content:// 两种URI方案
- 文件复制到应用私有目录，确保后续可访问

### 3.3 文件管理

#### 3.3.1 文件存储位置
**选择：应用私有目录（`getFilesDir()`）**

**理由：**

#### 3.3.2 文件导入流程

```java
// 1. 打开文件选择器
Intent intent = new Intent(Intent.ACTION_GET_CONTENT);
intent.setType("*/*");
intent.addCategory(Intent.CATEGORY_OPENABLE);
startActivityForResult(intent, REQUEST_CODE_PICK_FILE);

// 2. 处理选择的文件
@Override
protected void onActivityResult(int requestCode, int resultCode, Intent data) {
    if (requestCode == REQUEST_CODE_PICK_FILE && resultCode == RESULT_OK) {
        Uri uri = data.getData();
        
        // 3. 复制文件到应用私有目录
        String destPath = copyFileToPrivateDir(uri);
        
        // 4. 创建 DocumentItem
        DocumentItem item = new DocumentItem();
        item.setTitle(getFileName(uri));
        item.setFilePath(destPath);
        item.setType(DocumentType.fromFilePath(destPath));
        item.setFileSize(getFileSize(uri));
        
        // 5. 保存到数据库
        documentDao.insertDocument(item);
        
        // 6. 刷新列表
        refreshDocumentList();
    }
}
```

#### 3.3.3 文件删除策略
**删除文档时，同时删除数据库记录和文件**

```java
public boolean deleteDocument(long id) {
    // 1. 获取文档信息
    DocumentItem item = getDocumentById(id);
    if (item == null) return false;
    
    // 2. 删除文件
    File file = new File(item.getFilePath());
    if (file.exists()) {
        file.delete();
    }
    
    // 3. 删除数据库记录
    database.delete(TABLE_DOCUMENTS, COLUMN_ID + " = ?", new String[]{String.valueOf(id)});
    
    return true;
}
```

## 四、抽象层设计详解

### 4.1 设计理念

**核心思想：抽象层与具体实现分离**

虽然当前MVP阶段只实现了PDF功能，但整个架构设计为支持多种文档类型预留了扩展空间。所有核心组件使用 `Document` 抽象命名，而非 `Pdf` 具体命名。

### 4.2 抽象层组件

#### 4.2.1 数据模型层（抽象）

- **`DocumentType` 枚举**：定义所有支持的文档类型
  - 当前：`PDF`、`MARKDOWN`、`LATEX`、`TEXT`
  - 扩展：只需添加新枚举值，无需修改其他代码

- **`DocumentItem` 模型**：统一的文档数据模型
  - 包含所有文档类型的通用属性（标题、路径、类型、时间戳等）
  - 不包含特定类型的属性，保持通用性

#### 4.2.2 数据访问层（抽象）

- **`DocumentDao`**：文档数据访问对象
  - 所有CRUD操作与文档类型无关
  - 支持所有文档类型的统一操作（插入、查询、删除、更新等）

#### 4.2.3 UI展示层（抽象）

- **`DocumentFragment`**：文档列表Fragment
  - 展示所有类型的文档，按日期分组
  - 文档类型通过 `DocumentType` 区分，UI逻辑统一

- **`DocumentAdapter`**：文档列表适配器
  - 渲染所有类型的文档项
  - 根据 `DocumentType` 显示不同的类型标识

#### 4.2.4 查看器层（抽象接口 + 具体实现）

- **`DocumentViewerActivity`**：通用文档查看器
  - 类名使用抽象命名，表示支持多种文档类型
  - 内部根据 `document.getType()` 选择不同的渲染方式
  - 每种文档类型有独立的渲染方法（`renderPdf()`、`renderMarkdown()` 等）

### 4.3 具体实现层

#### 4.3.1 PDF实现（当前MVP）

- **渲染引擎**：`android.graphics.pdf.PdfRenderer`（系统API）
- **渲染方法**：`renderPdf()`
- **特定功能**：目录、翻页、缩放等PDF特有功能

#### 4.3.2 其他类型实现（预留接口）

- **Markdown**：`renderMarkdown()` - 使用 WebView + Markdown.js
- **Text**：`renderText()` - 使用 TextView
- **LaTeX**：`renderLatex()` - 使用 WebView + MathJax

### 4.4 命名规范

**抽象层命名（Document）：**
- `DocumentItem` - 文档数据模型
- `DocumentType` - 文档类型枚举
- `DocumentDao` - 文档数据访问
- `DocumentFragment` - 文档列表Fragment
- `DocumentAdapter` - 文档列表适配器
- `DocumentViewerActivity` - 文档查看器Activity

**具体实现命名（类型特定）：**
- `PdfRenderer` - PDF渲染引擎（系统API）
- `renderPdf()` - PDF渲染方法
- `TocAdapter` - PDF目录适配器（PDF特定功能）

**为什么这样设计？**
1. **可扩展性**：新增文档类型只需添加渲染方法，无需修改抽象层
2. **代码清晰**：抽象层与具体实现职责分明
3. **易于维护**：通用逻辑集中在抽象层，类型特定逻辑隔离在实现层

### 4.5 扩展新文档类型的步骤

以添加 EPUB 支持为例：

1. **添加类型枚举**：
   ```java
   // DocumentType.java
   EPUB("EPUB", ".epub"),
   ```

2. **添加渲染方法**：
   ```java
   // DocumentViewerActivity.java
   case EPUB:
       renderEpub();
       break;
   
   private void renderEpub() {
       // EPUB渲染实现
   }
   ```

3. **完成**：无需修改数据模型、数据库、列表展示等通用逻辑

## 八、技术决策

### 8.1 文件存储位置
**决策：应用私有目录**
- 理由：无需权限，更安全
- 路径：`getFilesDir()/documents/{type}/`

### 8.2 文档类型识别
**决策：根据文件扩展名自动识别**
- 方法：`DocumentType.fromFilePath(String filePath)`
- 扩展：支持手动指定类型（未来）

### 8.3 Markdown 渲染方案
**决策：第一阶段使用 WebView + Markdown.js**
- 理由：快速实现，无需额外依赖
- 后续：可优化为原生 Markdown 库

### 8.4 数据库版本管理
**决策：在 `LinkDbHelper` 中统一管理**
- 理由：保持数据库版本一致性
- 或者：创建独立的 `DocumentDbHelper`（推荐）

### 8.5 文档大小限制
**决策：暂不限制**
- 理由：让用户自由选择
- 后续：根据反馈添加限制

## 十、风险评估

### 10.1 技术风险
- **PDF 渲染性能**：大文件可能卡顿
  - 缓解：使用分页加载，显示加载进度
- **文件权限**：Android 11+ 文件访问限制
  - 缓解：使用 `ACTION_GET_CONTENT`，无需存储权限

### 10.2 用户体验风险
- **文件导入失败**：文件过大或格式不支持
  - 缓解：添加错误提示，限制文件大小

### 10.3 存储风险
- **存储空间**：大量文档可能占用过多空间
  - 缓解：显示文件大小，提供清理功能
