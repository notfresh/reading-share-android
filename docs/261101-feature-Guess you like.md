# 猜你喜欢(For You 推荐来源) — 2026-11-01

## 需求

阅读页数据来源新增第 5 个选项「猜你喜欢」(与 全部/置顶/标签/主题 并列,单选)。
每次进入实时计算 5 个推荐,读完这 5 个再算下一批 5 个,动态滚动。

## 入口与架构

- 入口唯一:阅读页数据来源下拉加「猜你喜欢」一项,不新做界面。
- 复用既有 `ReaderSource` 注册表扩展机制(对扩展开放、对修改关闭):
  - `ReaderSourceSpec.java` 加 `TYPE_FOR_YOU = "foryou"` 常量
  - 新建 `ForYouSource.java` 实现 `ReaderSource.loadPage(offset, limit)` — 算法全部收敛在这一个类
  - `ReaderSources.register()` 加一行注册
  - `LinkDao.java` 加推荐查询 SQL(权重聚合在 SQL 层做,不内存全量)
  - 下拉 binder + strings.xml / values-en 加「猜你喜欢」(走 i18n)
- 无状态、无新表、无新 SP 字段:每次实时算,回滚 = 单 commit revert。

## 实现原理与算法

**核心思想:你最常读哪类,就推荐哪类里你还没读的。**

数据源:
- 阅读历史 = `links_history` 表(每次真实阅读记一条,含 `visited_at` 毫秒时间戳)
  —— 注意:不是现有"阅读统计"用的 `links.timestamp × click_count`(那是保存时间,
  与实际阅读时间无关,这也是现有统计不准的根因)。
- 未读候选 = `links` 表全量减去已读。

算法步骤(每次进入实时执行):

1. **兴趣权重**:取最近 30 天阅读历史,按标签聚合阅读次数
   → 每个标签得权重 `w(tag) = 近 30 天该标签被阅读的次数`。
2. **候选打分**:每条未读链接
   `score = Σ w(tag)`,即它所属标签的权重之和;
   没标签的链接用域名权重兜底:`w(domain) = 近 30 天该域名被阅读的次数`。
3. **过滤**:已读过的链接(出现在 links_history 里的)剔除。
4. **排序取批**:按 score 降序取 5 个;同分随机打乱,避免每次推荐一样。

读完 5 个后阅读历史更新,下次重算权重自动漂移 → 推荐流随兴趣动态调整。

**无标签兜底链**(有标签 → 用标签;不够 → 补同域名未读;再不够 → 标题关键词相近):
没打过标签的内容靠「常去的站 + 常读的标题词」也能跑起来。
