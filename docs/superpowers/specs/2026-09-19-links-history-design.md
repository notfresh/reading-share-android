# 浏览历史设计

## 目标

为应用增加类似浏览器的 WebView 浏览历史。WebView 菜单和设置页都提供入口，两个入口复用同一个历史页面。历史记录不限制数量，由用户手动清空。

## 数据模型

在现有链接数据库中新增 `links_history` 表：

- `_id INTEGER PRIMARY KEY AUTOINCREMENT`
- `title TEXT`
- `url TEXT NOT NULL`
- `visited_at INTEGER NOT NULL`

数据库版本从 15 升到 16。升级只创建新表，不修改或删除现有链接数据。

每次 WebView 主页面成功完成加载时新增一条历史记录。相同 URL 的多次访问保留多条记录，以体现访问时间顺序。记录使用最终加载完成时的 URL 和页面标题；加载失败不记录。

## 数据访问

新增历史记录 DAO 能力：

- 插入一条历史记录。
- 按 `visited_at DESC` 查询全部记录。
- 按 id 删除单条记录。
- 清空全部历史记录。

历史记录独立于 `links` 表，因此修改、删除或归档保存链接不会影响浏览历史。

## 用户界面

新增一个历史页面 Activity 和列表适配器。列表项显示：

- 页面标题
- URL
- 访问时间

页面行为：

- 点击记录：使用记录 URL 打开 WebViewActivity。
- 删除单条记录：从数据库删除并刷新列表。
- 清空历史：二次确认后删除全部记录。
- 没有记录时显示空状态。

新增入口：

1. WebView 顶部菜单中的“浏览历史”。
2. 设置页中的“浏览历史”按钮。

两个入口启动同一个历史页面，不复制展示和删除逻辑。

## 记录时机

在 WebViewClient 的 `onPageFinished()` 中，仅对主框架页面记录。为避免同一次页面加载的重复回调，记录当前回调提供的 URL；不记录 `about:blank`、空 URL 或非网页资源。标题优先使用页面最终标题，标题为空时使用 URL 作为兜底标题。

## 错误处理

- 数据库插入失败不影响 WebView 页面使用，只记录日志。
- 历史页面加载失败显示空状态或错误提示，不影响返回应用。
- 删除失败保留当前列表项，并提示操作失败。
- 打开历史记录失败沿用 WebViewActivity 的 URL 校验和错误处理。

## 验证范围

- 首次启动自动创建 `links_history` 表。
- WebView 打开并完成一个主页面后出现一条记录。
- 同 URL 再次访问会新增记录。
- WebView 菜单和设置页都能打开同一历史页面。
- 点击记录能重新打开对应 URL。
- 单条删除和清空历史有效。
- 升级已有数据库不会丢失 `links` 表数据。
