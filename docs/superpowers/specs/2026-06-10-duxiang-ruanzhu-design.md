# 读享 V1.0 软件著作权登记申请 - 设计方案

## 1. 目标

为「读享 V1.0 软件」生成可提交至中国版权保护中心的软件著作权登记三件套：

1. 完整申请表 (.docx)
2. 用户手册 (.docx, 30–50 页)
3. 源程序代码鉴别材料 (2 份 PDF, 前 30 页 + 后 30 页, 每页 50 行; 另含首页 30 行 + 末页 30 行独立鉴别件)

公司信息(著作权人/开发者/联系信息)统一用占位符,用户最后一次性替换为真实信息后提交。

## 2. 项目结构

在 `docs/superpowers/` 下新增 `rz/` (软著拼音首字母) 目录,按三阶段组织:

```
docs/superpowers/rz/
├── README.md                      # 软著申请总说明(占位符一览 / 提交流程)
├── 01-申请表/
│   ├── 软著登记申请表.md          # 人可读源(检查用)
│   ├── 软著登记申请表.docx        # 最终交付
│   └── 生成脚本.py                # python-docx 复现脚本
├── 02-用户手册/
│   ├── 用户手册.md                # 人可读源(分章 Markdown)
│   ├── 用户手册.docx              # 最终交付
│   └── 生成脚本.py                # python-docx 复现脚本
├── 03-代码鉴别材料/
│   ├── 代码选取说明.md            # 选了哪些文件、为什么
│   ├── 源程序代码-首页30行.pdf    # 独立鉴别件
│   ├── 源程序代码-末页30行.pdf    # 独立鉴别件
│   ├── 源程序代码-前30页.pdf      # 主交付件
│   ├── 源程序代码-后30页.pdf      # 主交付件
│   ├── 源程序代码-前30页.md       # 人可读源
│   ├── 源程序代码-后30页.md       # 人可读源
│   └── 生成脚本.py                # reportlab 复现脚本
└── 04-提交前检查/
    └── 自检清单.md                # 统一替换 / 行数 / 页数 / 占位符清单
```

## 3. 三阶段关系与依赖

```
申请表 (源头) ── 提"软件全称/简称/版本/技术特点/模块说明" ──┐
                                                              ├──→ 用户手册 (消费申请表的字段)
用户手册 ── 提"功能列表/界面结构"                            │
代码鉴别材料 ── 提"程序总行数"                                │
                                                              ↓
                                                       软著中心提交
```

**交付顺序**: 申请表 → 用户手册 → 代码鉴别材料。每个交付件独立走 superpowers(spec → plan → 执行 → 检查),阶段间有用户确认检查点。

### 5.3 措辞原则
- 软件用途、技术特点、模块说明的描述语气**偏消费者使用场景**——"为消费者好用"原则
- 不堆砌技术术语,关键术语在第 1 章"软件概述"中先解释
- 中文(简体),术语首次出现给英文/缩写

### 6.3 截图处理
- **来源**: 优先复用 `image/`、`images/`、`app/src/main/res/drawable/` 中已有图片
- **缺失处**: 使用占位符 `图 X-Y:[此处插入 XX 界面截图]`,用户提交前可补
- **规格**: 至少 720×1280,统一编号(图 4-1 等)
- **每章 ≥ 2 张图**: 一张主界面 + 一张操作流程/状态机

### 6.4 措辞原则
- 描述"用户能看到什么、能做什么、怎么操作",避免源代码级讲解
- 操作步骤具体到"点击哪个按钮""输入什么内容""会看到什么结果"
- 关键术语在第 1 章"名词术语"中统一解释

### 7.1 交付件
- `03-代码鉴别材料/代码选取说明.md` - 选取理由与文件清单
- `03-代码鉴别材料/源程序代码-前30页.pdf` - 主交付件
- `03-代码鉴别材料/源程序代码-后30页.pdf` - 主交付件
- `03-代码鉴别材料/源程序代码-首页30行.pdf` - 独立鉴别件
- `03-代码鉴别材料/源程序代码-末页30行.pdf` - 独立鉴别件

- `03-代码鉴别材料/源程序代码-后30页.md` - 人可读源
- `03-代码鉴别材料/生成脚本.py` - reportlab 复现脚本

### 7.2 文件选取策略

**前 30 页(主流程,从用户打开 App 开始的路径)**:
- `MainActivity` ~300 行
- `ShareUtil` ~200 行
- `HomeFragment` ~250 行
- `LinkAdapter` / 其他 Adapter ~150 行
- `db/LinkDao` / `DatabaseHelper` ~200 行
- `model/Link` / `model/Tag` ~100 行
- `ui/tag/TagFragment` + `TagAdapter` ~200 行
- `ui/subject/SubjectDetailActivity` + Adapter ~150 行
- `ui/archive/ArchiveFragment` ~100 行
- `util/RecentTagsManager` / `util/StringUtil` / `util/ShareUtil` ~150 行
- 各 `OnClickListener` / `Menu` 回调
- 合计:约 30 页 × 50 行 = 1500 行

**后 30 页(核心底层,体现技术深度)**:
- `core/Synchronizer` ~400 行
- `util/PdfOutlineExtractor` ~200 行
- `util/BilibiliUrlConverter` ~100 行
- `util/CrawlUtil` ~150 行
- `util/ExportUtil` / `util/ImportUtil` ~200 行
- `util/ImageUtil` ~100 行
- `util/SubjectUtil` ~150 行
- `util/SwipeActionsHelper` ~100 行
- `ui/subject` + `ui/document` 部分控制器 ~300 行
- `WebViewActivity` + `WebViewManager` ~200 行
- `ClickStatisticsActivity` + `UserProfileActivity` ~200 行
- 零碎 util + config ~100 行
- 合计:约 30 页 × 50 行 = 1500 行

### 7.3 PDF 格式
- A4 纸 / 10 号等宽字体(Courier New)
- 页眉: `读享 V1.0 软件 - 源程序代码(前/后 30 页)` + 文件名 + 起始行号
- 页脚: 页码 `第 X 页 / 共 60 页`
- 标题页 1 页:含软件全称、版本、著作权人、文件列表、生成日期
- 之后 60 页:每页 50 行
- 单行 ≤ 80 字符;超出时行尾加 `// <第 X 页 第 Y 行>` 标记后换行
- 不夹空行、不夹图、不夹非 ASCII 字符
- 跨页时文件直接断到下一页,不在页中切断类成员

### 7.4 关键约束
- **总行数**: 申请表报 ≈ 3000 行(实际挑选出来的行数),不揭露 67 个文件/实际行数
- **公司信息处理**: 脚本仅做格式生成;代码原样保留,生成后人工检查并打码
- **不能出现的文件**: `R.java` 等 build 自动生成文件;`build/` 目录内容
- **首页 30 行 + 末页 30 行**: 作为独立鉴别件,每页 30 行,从前后 30 页各自提取

## 8. 工具与环境

- Python 3.10+
- `python-docx` (生成 .docx)
- `reportlab` 或 `fpdf2` (生成 .pdf)
- 复用项目现有 git / Read / Grep 工具
- 不调用 Android 模拟器(不实际截图)

## 9. 质量保证

### 9.1 硬约束(脚本必须保证)
- 用户手册页数:30 ≤ 页数 ≤ 50
- 代码 PDF:每页 50 行,每行 ≤ 80 字符
- 占位符:在所有交付件中按"占位符统一约定"表格一致出现
- 字体:Word 中正文宋体小四;PDF 中 Courier New 10 号
- 页眉页脚:每页都有

### 9.2 提交前自检清单(`04-提交前检查/自检清单.md`)
- 全部占位符已替换为真实信息
- 申请表 24 个栏目无空项
- 用户手册 8 章齐全,每章 ≥ 2 张图
- 代码鉴别材料 4 份 PDF 均生成,首页/末页可独立识别
- 排除 `R.java`、build/ 目录
- 单行字符数检查(无超 80 字符行)
- 总页数核对

## 10. 不在范围

- 实际申请提交操作(版权中心网站账号、上传 PDF、缴费等)
- 公司真实信息收集与替换(用户最后手动做)
- 实际启动 Android 模拟器抓取截图(用项目现有图片 + 占位符)
- 旧版变更历史说明
